# 上游每 30 分钟检查设计

## 目标

将 `Sync Upstream With Apophis Theme` 从每天检查一次调整为每 30 分钟检查一次，同时避免上游没有变化时重复构建镜像和发布二进制 Release。

## 触发规则

保留现有三种触发方式：

- `main` 分支推送；
- GitHub Actions 手动触发；
- 定时任务 `*/30 * * * *`，每 30 分钟触发一次。

## 上游变更判定

获取 `Wei-Shaw/sub2api` 指定引用后，读取上游最新提交 SHA。定时任务将该 SHA 与 `themed-release` 当前记录的上游 SHA 比较：

- SHA 相同：结束本次定时任务，不测试、不构建、不推送镜像、不发布 Release；
- SHA 不同：继续执行主题覆盖、测试、构建和发布；
- 无法读取旧 SHA：视为需要发布，保证首次运行可正常生成产物。

`main` 推送和手动触发不受上游 SHA 去重限制，以便主题自身修改后仍能重新发布。

## 发布链

检测到有效变化后继续沿用现有链路：

1. 在干净上游源码上应用 `theme/apophis`；
2. 检查主题漂移与 UTF-8 编码；
3. 运行前端 lint、typecheck、测试和生产构建；
4. 运行后端单元测试；
5. 发布不可变 Docker 镜像；
6. 更新 `themed-release`；
7. 更新 `latest`；
8. 成功后触发二进制 Release 工作流。

## 失败与回滚

任一检查或构建失败时，不更新 `themed-release`、`latest` 或二进制 Release，现有部署继续使用上一版产物。

## 验证

- YAML 能被解析；
- cron 为 `*/30 * * * *`；
- 定时触发且 SHA 相同时，发布步骤被跳过；
- 上游 SHA 变化时，完整发布步骤继续执行；
- `main` 推送和手动触发仍可发布主题修改。
