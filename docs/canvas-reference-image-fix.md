# 生图参考图读取失败：修复与验收

本地源码和 Chrome 复现已确认一条能产生截图相同报错的故障链路。仓库配置的线上入口 `https://api.kinght.top/canvas-app/` 已通过普通 HEAD 请求核验：HTTP 200，`img-src` 允许 `blob:`，`connect-src` 缺少 `blob:`、`data:`。如果截图来自该入口，线上响应头与复现条件一致。上游生图接口尚未调用。

## 根因

上传图片保存在 IndexedDB，页面通过 `blob:` 地址显示预览。生成前 `imageToDataUrl` 又对这个地址调用 `fetch`。站点默认 CSP 的 `img-src` 包含 `blob:`，`connect-src` 却只有同源、HTTPS 和本机 Agent 地址。因此预览成功，读取请求数据失败，最后显示“参考图读取失败，请换一张图片或重新上传”。

## 已实施修复

1. `imageToDataUrl` 通过 `storageKey` 读取原始 Blob，直接用 FileReader 转换，不再依赖预览地址。已有原图时，页面刷新或旧 object URL 被撤销仍能恢复。
2. 后端仅在 `/canvas-app` 和 `/canvas-app/` 子路径的响应 CSP 中，为 `connect-src` 补入 `blob:`、`data:`。这是 URL 形式导入和仅有 URL 的参考图所需的补充。自定义旧 CSP 同样处理；已有值不重复添加。
3. 两项修改都写入主仓库的构建适配器。后续上游同步会重用补丁；关键代码结构发生变化时停止构建，避免静默丢失修复。

## 本地验证

- 修改前，在真实 Chrome 中复现预览成功、参考图转换失败，未发出生图请求。
- 修改后，在原有严格 CSP 下，上传、原图转换、multipart 传输、旧 URL 撤销后恢复、刷新后从 IndexedDB 读取全部通过。
- 使用修复后 CSP 时，Data URL 导入和只有 blob URL 的参考图读取通过。
- 接收端校验文件 SHA-256 与原始图片一致。
- 浏览器实验使用本地接收端，不产生上游模型调用或费用。
- 18 项适配器与发布链路测试、后端 CSP 回归测试、Canvas TypeScript 检查和生产构建通过。构建保留了混用静态/动态导入与大分包提示，不影响产物生成。

浏览器证据和复现脚本位于 `output/canvas-reference-image-fix/`。原始被修改文件保存在同一目录，便于比对。

## 发布时必须一起生效

将主仓库补丁纳入正常发布，构建并部署同时包含 Canvas 前端与 Go 后端的同一版本。仅刷新页面、重启旧镜像或拉取尚未包含本次修复的 latest 都不会应用代码修改。

部署后，检查浏览器实际加载的 `/canvas-app/` HTML 响应：

- `connect-src` 必须同时包含原有来源、`blob:`、`data:`。
- 如果 Nginx、网关或 CDN 还附加另一份 CSP，每一份约束都需要允许 Canvas 的相关读取；多个 CSP 同时生效，较宽松的一份不会覆盖较严格的一份。只调整对应路径的策略，不关闭全站 CSP。
- 让 HTML/CDN 缓存更新到新版本，然后重新加载页面。不要清除站点数据或 IndexedDB，这会删除本地原图与历史。
- 用本地 PNG 上传并生成一次，再刷新页面复用参考图。Network 中应出现实际图片编辑请求，并检查上游返回结果。

如果之前原始 Blob 已经被删除，仅剩失效 URL 或缩略图，则需要重新上传原文件；修复不能恢复已经丢失的原始字节。

## 回滚

部署回滚到上一个固定版本镜像，保留数据库、Volume 与浏览器 IndexedDB。源码回滚只撤销本次适配器和 CSP 修改，保留工作区已有改动。
